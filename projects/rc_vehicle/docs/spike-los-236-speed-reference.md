# Spike LOS-236 — Аппаратный референс скорости для EKF: отчёт

**Задача:** [LOS-236](https://linear.app/lostpointer/issue/LOS-236).
**Связано:** [LOS-233](https://linear.app/lostpointer/issue/LOS-233) (софт-якорь:
мотор-модель + NHC + guard — база, в которую встраивается датчик),
[LOS-237](https://linear.app/lostpointer/issue/LOS-237) (GNSS как абсолютный
референс — отдельный спайк).
**Код не менялся** — исследовательский отчёт.

## 1. Цель и рамки

EKF ([`vehicle_ekf.hpp`](../firmware/common/vehicle_ekf.hpp)) оценивает
скорость интегрированием IMU; LOS-233 удерживает её от расходимости
псевдо-измерением `v ≈ gain·throttle` (`UpdateSpeed`, слабый шум
`speed_meas_noise = 4.0`). Это открытый контур: горка, пробуксовка, разряд
батареи ломают линейную модель. Спайк сравнивает три кандидата на
**независимое измерение скорости** и даёт рекомендацию + эскиз интеграции.

## 2. Текущее железо и ограничения

Факты из [`bom_ru.md`](bom_ru.md), [`wiring_diagram.md`](wiring_diagram.md),
[`config.hpp`](../firmware/esp32_s3/main/config.hpp),
[`pwm_control.cpp`](../firmware/esp32_s3/main/pwm_control.cpp):

| Что | Состояние |
|---|---|
| Шасси | Himoto SCT-16 4WD 1:16 (RTR) |
| Мотор / ESC | **Brushed** мотор + стоковый brushed ESC, вход — servo-PWM 50 Гц, 1000–2000 мкс |
| Управление PWM | ESP32-S3 **LEDC** (GPIO14 → ESC, GPIO21 → серва); MCPWM-периферия **полностью свободна** (в доках упоминание «MCPWM» устарело) |
| Занятые шины | SPI2 (GPIO10–13): IMU MPU-6500; I2C (GPIO8/9): магнитометр MMC5983MA; RC capture: GPIO16/17 |
| Свободные GPIO | 1–4, 6–7, 15, 18, 38–47 |
| Свободная периферия | MCPWM (capture-юниты), PCNT, RMT-каналы |

Ключевой факт для варианта 1: **цифровой телеметрии у ESC нет и быть не
может** — сток brushed. eRPM реализуем только вместе с апгрейдом
мотор + ESC на brushless.

## 3. Вариант 1 — ESC-телеметрия (bidirectional DShot / eRPM)

**Что требуется:** замена силовой части на brushless combo + ESC с прошивкой
BLHeli_32 / Bluejay (BLHeli_S) / AM32 — все три поддерживают bidirectional
DShot (eRPM возвращается по той же сигнальной линии, EDT добавляет
температуру/напряжение). Для машинки нужен ESC с реверсом — это сужает выбор
до автомобильных brushless ESC (у большинства из них DShot-телеметрии нет)
либо дроновых AM32 с включённым 3D-режимом (реверс есть, но поведение «газ
вокруг нуля» отличается от автомобильного: нет drag brake, нейтраль — середина
диапазона).

**Приём на ESP32-S3:** RMT-периферия, готовые библиотеки есть
([DShot-ESP32RMT](https://github.com/MichelJansson/DShot-ESP32RMT),
[DShotRMT](https://github.com/derdoktor667/DShotRMT)); для bidir обязателен
внешний pull-up ~2 кОм на 3.3 В. Это **замена всего тракта газа**:
`pwm_control.cpp` (LEDC 50 Гц) → DShot-драйвер, т.е. затрагивается критичный
путь управления, а не только сенсорика.

**Пересчёт eRPM → скорость:**

```
v = (eRPM / pole_pairs) / 60 · (1 / i_total) · π · D_wheel
```

`pole_pairs` — пары полюсов мотора, `i_total` — полное передаточное число
(пиньон/спур × редуктор дифференциала; для SCT-16 нужно измерить),
`D_wheel` — диаметр колеса под нагрузкой.

**Точность:** измеряется вал мотора → пробуксовку колёс видно частично
(мотор крутится быстрее фактической скорости), проскальзывание в трансмиссии
и юз при торможении не видны. При заблокированных колёсах (юз) eRPM = 0 при
ненулевой скорости — то же вырождение, что у холла.

**Стоимость:** brushless combo 1/16 (например, Hobbywing QuicRun Fusion /
обычный 2435-мотор + ESC) — порядка $40–80 (≈4–8 тыс ₽), плюс риск, что
конкретный ESC не умеет bidir DShot. Самый дорогой и самый инвазивный
вариант.

## 4. Вариант 2 — холл-датчик / энкодер на трансмиссии

**Механика:** 2–4 неодимовых магнита (Ø3–4 мм) в спур-шестерню или чашку
колеса + датчик Холла (A3144/US1881 — цифровые, <100 ₽) на кронштейне.
Доработка обратимая, силовая часть не трогается.

**Электроника/захват:** один свободный GPIO (15 или 18). Два режима на выбор:

* **MCPWM capture** — измерение периода между импульсами: точен на малых
  скоростях (как раз зона, где сейчас «шум» — `stabilization_pipeline.cpp`
  честно говорит «без энкодеров speed < 0.5 м/с — зона шума»);
* **PCNT** — счёт импульсов за окно: проще, но на 500 Гц-цикле при малой
  скорости импульсов слишком мало (при 4 магнитах на колесе и 0.5 м/с —
  ~11 Гц, т.е. свежая оценка раз в ~90 мс). Вывод: **capture по периоду —
  правильный режим**, публикация последнего измерения с меткой времени +
  таймаут «нет импульсов = стоим».

**Ограничения:**

* **Нет знака направления.** Один датчик даёт |v|; знак брать из
  commanded throttle (как уже делает мотор-модель) либо ставить второй датчик
  со сдвигом (квадратура) — на первом этапе достаточно знака от throttle.
* Место установки: магниты на чашке колеса → меряем скорость колеса
  (пробуксовка видна как рассогласование с IMU — полезный сигнал для
  детекции), на спуре → эквивалент варианта 1 по наблюдаемости, но без
  замены ESC.
* Вибрации/грязь — нужен дребезг-фильтр по минимальному периоду.

**Стоимость:** ~100–300 ₽ (датчик + магниты + клей/кронштейн). Самый дешёвый
и точный по продольной скорости вариант; цена — механическая возня.

## 5. Вариант 3 — Optical flow PMW3901 (+ VL53L1X)

Уже описан как опция в [`bom_ru.md` §«Оптический датчик скорости»](bom_ru.md)
(помечен «не куплено»).

**Что даёт:** смещение по **двум осям** относительно земли → единственный
вариант, который измеряет и `vy` (настоящее измерение бокового скольжения
вместо NHC-эвристики) и не зависит от пробуксовки колёс.

**Подключение:** SPI2 уже разведена (IMU), PMW3901 вешается отдельным CS на
свободный GPIO; VL53L1X — на существующую I2C (адрес 0x29, конфликтов с
MMC5983MA/0x30 нет). Драйвер несложный (регистры motion burst), но это ещё
два устройства в 500 Гц-цикле — опрос выносить из critical path (тот же
принцип, что с телеметрией).

**Главный риск — рабочая высота.** PMW3901 фокусируется от **80 мм** до
бесконечности, а клиренс шасси 1/16 — ~25–35 мм. Придётся ставить датчик
выше днища (в нише кузова) и проверять фокус, либо брать модуль с другой
оптикой (PMW3901MB-модули с линзой под малую высоту редки). Плюс
классические ограничения: текстура поверхности (гладкий пол/ковёр с мелким
ворсом — плохо), освещение (в помещении может понадобиться IR-подсветка,
см. bom_ru), грязь на окне.

**Масштаб:** сырой выход — пиксельные дельты; для пересчёта в м/с нужна
высота (фиксированная установка ≈ константа, но подвеска дышит ±10 мм —
на малой высоте это большая относительная ошибка; отсюда рекомендация ToF).

**Стоимость:** модуль PMW3901 ≈ $13–18 (≈1500–2000 ₽:
[eBay](https://www.ebay.com/itm/406485631117),
[Holybro](https://holybro.com/products/pmw3901-optical-flow-sensor),
[Pimoroni](https://shop.pimoroni.com/en-us/products/pmw3901-optical-flow-sensor-breakout));
VL53L1X ≈ 300–700 ₽. Итого ~2–3 тыс ₽.

## 6. Матрица сравнения

| Критерий | 1. eRPM (DShot) | 2. Холл на трансмиссии | 3. PMW3901 (+ToF) |
|---|---|---|---|
| Что измеряет | обороты мотора (до трансмиссии) | скорость колеса/спура | скорость **относительно земли**, обе оси |
| Видит пробуксовку колёс | частично | на чашке колеса — как рассогласование с IMU | **да** (иммунен) |
| Точность на малых скоростях | хорошая (eRPM живой) | **хорошая** (capture по периоду) | средняя (зависит от текстуры/высоты) |
| Знак скорости | есть (из направления) | нет (знак от throttle / 2-й датчик) | есть |
| Стоимость | $40–80 (апгрейд combo) | **~100–300 ₽** | ~2–3 тыс ₽ |
| Доработка HW | замена мотора+ESC, pull-up | магниты + кронштейн | монтаж вниз, вопрос высоты 80 мм |
| Софт | DShot-драйвер **вместо LEDC** — инвазивно в тракт газа | capture-драйвер, изолирован | SPI+I2C драйверы, вынос из 500 Гц-цикла |
| Риски | ESC с реверсом и bidir DShot — редкое сочетание | вибрации/дребезг | фокус < 80 мм, поверхность, свет, грязь |

## 7. Эскиз расширения HAL

В [`vehicle_control_platform.hpp`](../firmware/common/vehicle_control_platform.hpp),
с **дефолтной реализацией** (не pure virtual) — существующие платформы и моки
не ломаются:

```cpp
/**
 * @brief Измерение скорости от аппаратного датчика.
 *
 * Источник — холл-датчик/энкодер (только vx, знак может браться из
 * throttle) или optical flow (vx + vy). Платформа публикует последнее
 * готовое измерение; свежесть определяется по timestamp_us.
 */
struct SpeedMeasurement {
  float vx_ms{0.0f};              ///< Продольная скорость [м/с], знаковая
  std::optional<float> vy_ms{};   ///< Боковая скорость [м/с] (optical flow)
  float r{0.05f};                 ///< Рекомендуемый шум измерения [м²/с²]
  uint32_t timestamp_us{0};       ///< Метка времени платформы (GetTimeUs)
};

/// Инициализация датчика скорости (nop по умолчанию — датчика нет).
[[nodiscard]] virtual std::expected<void, PlatformError> InitSpeedSensor() {
  return {};
}

/// Последнее измерение скорости; nullopt — датчика нет или данных ещё нет.
[[nodiscard]] virtual std::optional<SpeedMeasurement> ReadSpeedSensor() {
  return std::nullopt;
}
```

Замечания:

* `r` отдаёт платформа: capture-драйвер знает свою дисперсию (растёт на
  сверхмалых скоростях), optical flow может деградировать `r` при слабом
  качестве трекинга (у PMW3901 есть surface quality-регистр).
* Пересчёт импульсы→м/с (магниты, передаточное, диаметр) — константы уровня
  платформы/NVS, EKF получает уже м/с.

## 8. Встраивание в EKF

Точка входа готова с LOS-233 — `VehicleEkf::UpdateSpeed(v_meas, r_speed)`
(H = [1,0,0,0], Joseph-form). Изменения локализованы в
`ControlLoopProcessor::UpdateSensorsAndEkf()`:

1. Есть свежее `ReadSpeedSensor()` (timestamp моложе, скажем, 100 мс) →
   `UpdateSpeed(meas.vx_ms, meas.r)` с **малым** шумом (~0.05–0.2 против
   4.0 у мотор-модели). Мотор-модель при этом можно оставить включённой —
   её слабый якорь ничего не портит и остаётся фолбэком.
2. Нет данных датчика (отказ/таймаут) → текущее поведение LOS-233 без
   изменений (мотор-модель + NHC). Деградация мягкая по построению.
3. Для optical flow дополнительно: `vy_ms` → скалярный update столбца vy
   (обобщение `UpdateNonHolonomic`: то же `ScalarMeasUpdate(1, z, r)`, но с
   реальным `z` вместо нуля) — заменяет NHC, когда измерение есть.
4. Конфиг: `FilterConfig` дополняется `speed_sensor_enabled` (+ его шум как
   floor для `meas.r`); телеметрия — сырое `vx_ms` датчика рядом с оценкой
   EKF (валидация по логам, как делали для физ-модели SIL).

## 9. Вердикт

**Рекомендация: вариант 2 — холл-датчик на трансмиссии (первый этап),
PMW3901 — второй этап, eRPM — не делать отдельно.**

* Холл закрывает главную боль (независимый |v| продольной скорости) за
  ~300 ₽ и вечер механики, точен именно на малых скоростях, не трогает тракт
  газа, capture-периферия свободна. Знак от throttle — приемлемый компромисс
  для первого этапа.
* PMW3901 — единственный источник честного `vy` и иммунитета к пробуксовке;
  делать после холла и только после проверки фокуса на реальной высоте
  установки (главный технический риск). Позиции уже в BOM.
* eRPM осмыслен только как **бесплатный бонус планового апгрейда на
  brushless** — заводить отдельную задачу не стоит: дорого, инвазивно
  (LEDC→DShot в тракте газа), а наблюдаемость не лучше холла на спуре.

**Следующие шаги** (отдельные задачи в Linear, после закрытия LOS-233):

1. Закупка: холл-датчики + магниты (сразу с запасом), PMW3901 + VL53L1X
   (позиции из bom_ru).
2. Механика + драйвер холла (MCPWM capture, GPIO15), `InitSpeedSensor` /
   `ReadSpeedSensor` в HAL по эскизу §7.
3. Интеграция в EKF по §8 + телеметрия сырой скорости, валидация на логах.
4. Спайк-проверка PMW3901 на столе (фокус/высота/поверхности) до врезки в
   шасси.
