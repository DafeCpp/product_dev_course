# Профили мотора и ESC (LOS-19)

## Решение: одна прошивка на все моторы

Прошивка одна для любых мотора и ESC. Выход газа настраивается **профилем мотора** (`MotorConfig`), который хранится в NVS и читается один раз при загрузке. Флаги компиляции остаются только для того, что зависит от разводки платы (пины, интерфейс магнитометра).

Почему не флаги компиляции:

- ESC меняют прямо на машинке. С флагами легко прошить бинарник не под тот ESC, а CI пришлось бы собирать и тестировать матрицу сборок.
- Профиль меняется из веб-интерфейса, как и остальные настройки, без пересборки.

## Профили

| Профиль | Железо | Выход газа |
|---|---|---|
| `brushed_pwm` (по умолчанию) | штатный коллекторный мотор + brushed ESC | servo-PWM 50 Гц, GPIO14 |
| `vesc_pwm` | Flipsky Mini FSESC 4.20 (VESC 4.12) + GoolRC S2440 4000KV | тот же PWM, на стороне VESC приложение PPM |

Оба профиля управляют газом одинаково: PWM 50 Гц на общем с сервой таймере LEDC. Отличие `vesc_pwm` в том, что при загрузке запускается опрос телеметрии VESC по UART (см. ниже).

Дальше по плану:

1. Скорость для EKF из eRPM (вариант 1 из `spike-los-236-speed-reference.md`). У мотора 2 пары полюсов: `rpm_мотора = eRPM / 2`. Для скорости колеса нужны ещё передаточное число и диаметр колеса.
2. По желанию: управление газом по UART (`SET_CURRENT` или `SET_RPM`) вместо PWM.

## Параметры

| Поле | По умолчанию | Ограничения | Смысл |
|---|---|---|---|
| `min_us` | 1000 | ≥ 500 | полный назад/тормоз |
| `neutral_us` | 1500 | ≥ `min_us` + 100 | нейтраль, её же выдаёт failsafe |
| `max_us` | 2000 | ≥ `neutral_us` + 100, ≤ 2500 | полный газ |
| `deadband` | 0 | 0…0.5 | при \|газ\| ≤ deadband выдаётся нейтраль, остальной ход растягивается без скачка |
| `reversed` | false | — | инвертирует направление |

Если запись в NVS невалидна или её нет, используется `brushed_pwm` по умолчанию: газ работает ровно как до появления профилей. Мёртвая зона здесь служит для подавления дрожания около нуля. Порог трогания с места (`min_effective_throttle`, LOS-169) остаётся в MotionDriver.

## Как сменить профиль

Веб-интерфейс, панель **«Мотор / ESC»**: выбрать профиль, при необходимости поправить диапазон и нажать «Сохранить». Новый профиль **применяется после перезагрузки**. Выход газа не перенастраивается на ходу, чтобы смена не застала мотор под нагрузкой. Пока профиль не применён, в заголовке панели горит «нужна перезагрузка».

WebSocket-команды:

```jsonc
// запрос
{"type": "get_motor_config"}
// ответ: active — с чем работает выход сейчас, saved — что применится после перезагрузки
{"type": "motor_config",
 "active": {"profile": "brushed_pwm", "min_us": 1000, "neutral_us": 1500, "max_us": 2000, "deadband": 0, "reversed": false},
 "saved":  {"profile": "vesc_pwm",    "min_us": 1000, "neutral_us": 1500, "max_us": 2000, "deadband": 0, "reversed": false},
 "pending_reboot": true}

// сохранить: все поля необязательны, отсутствующие берутся из сохранённого профиля.
// Если profile меняется, отсутствующие поля берутся из значений по умолчанию нового профиля.
{"type": "set_motor_config", "profile": "vesc_pwm", "deadband": 0.03}
// сбросить на значения по умолчанию (удаляет запись NVS)
{"type": "set_motor_config", "reset": true}
// поле неверного типа (например, "reversed": "false" или "deadband": null) — ошибка, ничего не сохраняется
// ответ: те же поля плюс ok и error (invalid_profile | invalid_config | nvs_error)
{"type": "set_motor_config_ack", "ok": true, "active": {...}, "saved": {...}, "pending_reboot": true}
```

## Телеметрия VESC по UART

Только для профиля `vesc_pwm`. Фоновая задача на core 0 каждые 20 мс (50 Гц) шлёт `COMM_GET_VALUES` и хранит последний ответ. Газ при этом идёт по PWM, UART только читает. Поэтому обрыв провода или зависший VESC не мешают управлению и failsafe, пропадает только телеметрия.

Подключение (UART1, логика 3.3 В):

| ESP32-S3 | VESC |
|---|---|
| GPIO7 (RX) | TX |
| GPIO6 (TX) | RX |
| GND | GND |

Пины и скорость задаются в `esp32_s3/main/config.hpp` (`VESC_UART_*`).

В WS-кадре `telem` появляется блок `esc`. Если ответа нет дольше 200 мс, блок пропадает.

```jsonc
"esc": {"erpm": 12000, "v_in": 11.8, "i_motor": 3.2, "i_in": 1.1, "duty": 0.21,
        "t_fet": 34.5, "t_motor": 0, "tacho": 98765, "fault": 0, "age_ms": 12}
```

`erpm` — электрические обороты, со знаком направления. `i_in` отрицателен при рекуперации. `fault` — код `mc_fault_code` VESC, 0 означает «нет ошибки». Датчика температуры у GoolRC S2440 нет, поэтому `t_motor` около 0. В веб-интерфейсе эти значения выводятся в панели «Телеметрия».

### Запись в лог поездки

Те же данные пишутся в кадр лога PSRAM (100 Гц), поэтому попадают в CSV-выгрузку из веб-интерфейса и в UDP-запись (`tools/udp_telem.py`). Колонки: `esc_erpm`, `esc_v_in`, `esc_i_motor`, `esc_i_in`, `esc_duty`, `esc_t_fet`, `esc_fault` и `esc_valid`. Если `esc_valid` = 0, значит телеметрии в этот момент не было (профиль `brushed_pwm`, VESC не отвечает или ответ старше 200 мс), и остальные `esc_*` равны нулю. VESC опрашивается на 50 Гц, поэтому в соседних кадрах лога значения повторяются.

Из-за новых полей кадр вырос со 132 до 160 байт, а буфер сократился с 52000 до 42000 кадров (≈ 7 мин вместо 8.7). Версия UDP-пакета поднята до 2.

## Подготовка VESC перед первым запуском

Делается в VESC Tool, прошивка за это не отвечает:

- App: **PPM and UART** (газ по PPM, телеметрия по UART), UART 115200 бод. PPM: диапазон 1000–2000 мкс, центр 1500 мкс.
- **Таймаут PPM**: при пропаже сигнала мотор отпускается. Это вторая линия защиты после failsafe прошивки.
- Лимит ERPM около 50 000, это ~25 000 об/мин при 2 парах полюсов (предел контроллера 60 000 ERPM). Без нагрузки на 3S мотор 4000KV раскрутился бы до ~52 000 об/мин.
- Лимит тока батареи не выше 15–20 А (разъём XT30).
