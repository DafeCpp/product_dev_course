# FW-R15 — Кастомная настройка режима теряется при переключении

**Приоритет:** MEDIUM
**Зона:** `common/stabilization_manager.cpp`, NVS-хранилище stab-конфига
**Статус:** в работе

## Симптом (нашёл пользователь)

1. В режиме (напр. Normal) выставить `slew_steering` = 10, нажать «Сохранить».
2. Переключиться в другой режим.
3. Вернуться в прежний режим, нажать «Загрузить».
4. `slew_steering` показывает значение по умолчанию, а не сохранённые 10.

## Корневая причина

Две связанные проблемы:

1. **Единый слот NVS.** Конфиг стабилизации хранился одним blob'ом (namespace
   `stab_cfg`, key `config`). Сохранение любого режима затирало настройку
   предыдущего.
2. **Затирание дефолтами при смене режима.** `StabilizationManager::SetConfig`
   при `mode != current_mode` вызывал `ApplyModeDefaults()`, перезаписывая
   пользовательские `slew_throttle`/`slew_steering`/PID хардкод-дефолтами
   режима (`drive_modes.cpp`).

При этом UI-«сохранение» и смена режима идут через один хендлер
`set_stab_config`, который **всегда** персистит (`persist=true`). Сценарий:

| Шаг | Действие | NVS после |
|-----|----------|-----------|
| 1 | Normal, slew=10, Save | `{Normal, slew=10}` |
| 2 | Переключение в Sport | `{Sport, slew=default}` ← 10 потеряны |
| 3 | Возврат в Normal | `{Normal, slew=default}` |
| 4 | Load | читает default |

## Решение — per-mode хранение в NVS

- **NVS** (`stabilization_config_nvs`): отдельный слот на каждый `DriveMode`
  (ключи `cfg0`..`cfg4`) + ключ `active` (последний активный режим, для
  восстановления при старте). `Save()` пишет в слот `config.mode` и обновляет
  `active`. Добавлен `Load(DriveMode)`; `Load()` (без аргумента) грузит активный
  режим. Миграция со старого ключа `config` (грузится один раз и переносится в
  per-mode слот). `Erase()` чистит все слоты + `active` + legacy.
- **Платформа** (`VehicleControlPlatform`): добавлен
  `LoadStabilizationConfig(DriveMode)`; ESP32-реализация проксирует в NVS.
- **Менеджер** (`StabilizationManager::SetConfig`): при смене режима вместо
  `ApplyModeDefaults()` сначала пытается восстановить сохранённый профиль режима
  через `platform_.LoadStabilizationConfig(mode)`; дефолты применяются только
  если для режима ничего не сохранено. Поля, пришедшие в запросе вместе со
  сменой `mode`, относятся к старому режиму и игнорируются.

После фикса: слот Normal не затирается сохранением Sport (шаг 2), а возврат в
Normal (шаг 3) восстанавливает `slew=10`.

## Критерии приёмки

- [x] Host-тест: Normal slew=9 → Sport (дефолты) → Normal восстанавливает 9
  (`StabilizationManagerTest.ModeSwitch_RestoresSavedPerModeConfig`).
- [x] Host-тест: инлайн-поля при смене режима не «протекают» в новый режим
  (`ModeSwitch_IgnoresInlineFieldsForNewMode`).
- [x] Существующие тесты save/load (`FakePlatform`) зелёные.
- [ ] Железо: настроить slew в нескольких режимах, переключаться туда-обратно,
  перезагрузить машинку — настройки каждого режима сохраняются независимо.
- [ ] Миграция: после прошивки поверх старого формата конфиг не теряется
  (legacy `config` подхватывается один раз).
