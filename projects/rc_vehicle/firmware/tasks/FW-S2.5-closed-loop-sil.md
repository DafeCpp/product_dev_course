# FW-S2.5 — Closed-loop SIL (interactive): Python-модель ↔ `sim_host`

**Источник:** декомпозиция эпика [FW-S2](FW-S2-sil-physics-model-epic.md), 2026-06-17
**Тип:** инфраструктура тестирования (Фаза 3 — closed-loop SIL)
**Язык:** Python (+ exe из [FW-S2.1](FW-S2.1-sim-host-stdio-platform.md))
**Приоритет:** MEDIUM
**Статус:** [x] Готово
**Файлы:** `firmware/sim/simlib/closed_loop.py` (`ClosedLoopSim`),
`firmware/sim/tests/test_closed_loop.py`.

## Зачем

Замкнуть выход прошивки на физ-модель: позволяет гонять сценарии, которых нет в
записях (step-руль, занос, потеря сигнала), тюнить ПИД/стабилизацию и **воспроизводить
найденные баги как регрессии до железа**. В контуре — полный тракт прошивки
(калибровка/Madgwick/EKF), потому что модель отдаёт сырьё через `sim_host`.

## Объём

- **Контур (interactive-режим `sim_host`):** PWM из exe → модель Фазы 2
  ([FW-S2.4](FW-S2.4-python-vehicle-model.md)) интегрирует шаг dt → синтез сырого
  кадра → обратно в exe на следующем тике. Детерминированный прогон на фиксированном
  шаге (2 мс = 500 Гц), логическое время.
- **Сценарии без железа:** step-руль, рамп газа, синусоида руля, потеря сигнала
  (failsafe [FW-R1](FW-R1-failsafe-trim-override.md)), детский режим (лимит скорости
  **FW-R21**), занос
  ([FW-R2](FW-R2-oversteer-slip-rate-spike.md)), задний ход
  (**FW-R22**).
- **Регресс на найденных багах:** воспроизвести
  **FW-R17** /
  **FW-R21** /
  **FW-R22** /
  **FW-R23** как closed-loop кейсы.
- Проверка EKF-оценки скорости против «истинной» скорости модели (перекликается с
  ненадёжностью `ekf_vx`/большой `ekf_vx_var`, замеченной на логах).

**Ограничение:** SIL верен ровно настолько, насколько верна модель Фазы 2 — поэтому
ассерты пишем на **качественные** свойства (знак реакции, отсутствие осцилляций,
сходимость), не на точные числа. Достоверность модели обеспечивает
[FW-S2.6](FW-S2.6-model-validation.md).

## Критерии приёмки

- [x] Closed-loop контур замыкается через interactive `sim_host`, детерминированно
  (тест `test_deterministic_runs`).
- [x] 7 сценарных кейсов: рамп газа, step-руль (симметрия), failsafe, задний ход,
  финитность/диапазон — зелёные в pytest (всего по `firmware/sim`: 23).
- [x] Регресс **FW-R17** воспроизведён: прямая команда с буста → нет фантомного
  руля (max |applied steering| = 0).

**Поправка к плану:** kids-лимит (FW-R21) и FW-R23 (висячий конфиг при смене режима)
требуют команды установки drive-mode/конфига в протоколе `sim_host` (сейчас режим =
Normal по умолчанию). Вынесено в follow-up — небольшое расширение протокола FW-S2.1
(`set-config`). Занос/oversteer (FW-R2) — на динамической модели с высокими
боковыми, тоже follow-up к набору сценариев.
