# FW-RF3 — ImuHandler::Update: дедупликация mag-проекции и разбиение

**Источник:** `firmware/CODE_REVIEW.md` → Review 2026-06-10, RF3
**Приоритет:** MEDIUM (рефакторинг)
**Статус:** [ ] Не начато
**Файлы:** `common/control_components.cpp:53-192`

## Проблема

`ImuHandler::Update()` — ~140 строк, несколько зон ответственности. Проекция
магнитометра на калибровочную плоскость продублирована дважды:

- `:140-150` — для вычисления `heading_deg_`;
- `:171-177` — для подачи в Madgwick (этот дубль уходит при FW-R3).

## Предлагаемое решение

1. Извлечь приватные методы:
   - `ReadAndCalibrateImu(now_ms)` — чтение, FeedSample, Apply, LPF;
   - `UpdateVehicleFrame()` — установка/сброс опорной СК по статусу калибровки;
   - `UpdateMagAndHeading(now_ms)` — чтение mag, калибровка, PCA-heading,
     опорный курс;
   - `FeedMadgwick(dt_sec)` — выбор 6DOF/9DOF и вызов фильтра.
2. Вынести `ProjectMagOntoCalibPlane(const MagData&, const MagCalibData&)`
   → `{comp1, comp2}` (или полный проецированный вектор) — единственное место
   с математикой проекции.

## Связанные задачи

- **FW-R3** — меняет ту же ветку 9DOF; делать ПОСЛЕ FW-R3 (или одной веткой:
  сначала фикс поведения с тестом, затем механический рефакторинг).

## Объём работ

- [ ] Извлечение методов без изменения поведения
- [ ] Существующие тесты компонентов проходят; при наличии — добавить тест на heading при наклонной калибровочной плоскости

## Критерии приёмки

`Update()` ≤ ~30 строк (последовательность вызовов); математика проекции
существует в одном экземпляре; тесты зелёные.
