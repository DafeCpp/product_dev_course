# FW-S3 (spike) — Достоверность оценки скорости EKF (vx)

**Тип:** исследование (spike). Артефакт — замеры + рекомендация/ADR, не код в проде.
**Приоритет:** LOW
**Статус:** [ ] открыта

## Контекст / зачем

EKF машины — IMU-only (без датчика колёс): `vx`/`vy` интегрируются из ускорений
и дрейфуют (см. `common/vehicle_ekf.hpp:68-70`). Это уже ударило по двум задачам:

- **FW-R21** — kids speed limit (`max_speed_ms`) завязан на `ekf->GetSpeedMs()`
  и потому ненадёжен; рабочий лимит — статический `throttle_limit`.
- **FW-R22** — направление движения (реверс) пришлось брать по знаку команды
  газа, а не по знаку `vx`, именно из-за недостоверности `vx`.

## Наблюдения из логов (17_06)

- `telemetry_log_normal_17_06.csv`: `ekf_vx_var` доходит до **193** (std ~14 м/с
  при реальной скорости <1 м/с), `> 10` в **54%** кадров; на t≈20.7 с резкий
  сброс 193→0.1 (ковариация после ZUPT/Reset).
- Реальная скорость в заездах <0.85 м/с — то есть абсолютная оценка `vx`
  на порядок «шумнее» самой величины.

## Вопросы исследования

1. Откуда рост `vx_var` до 193: процессный шум без измерения скорости?
   Корректно ли работает ZUPT-гейтинг (порог по throttle)?
2. Можно ли сделать `GetSpeedMs()` пригодным для лимита/направления без
   датчика колёс (улучшенный ZUPT, доверие по `vx_var`, оценка по PWM/модели)?
3. Стоит ли добавить датчик (Hall на валу / оптопара / optical flow) — что
   проще на текущем шасси, какая точность нужна для kids speed limit.

## Артефакт

- Замеры `vx`/`vx_var` vs реальная скорость (несколько заездов, разные режимы).
- Рекомендация: (а) аппаратный датчик скорости, либо (б) программное доверие
  (`vx_var`-gating лимита) + честная пометка «best-effort», либо (в) отказ от
  EKF-скорости в пользу throttle/модели для лимита.
- При выборе аппаратного пути — ADR (расширение вектора состояния EKF под
  измерение скорости, см. `vehicle_ekf.hpp:70`).

## Связанные задачи

- **FW-R21** — kids speed limit (вторичная ненадёжность EKF-скорости).
- **FW-R22** — направление реверса берётся по газу из-за недостоверности `vx`.
- **FW-S2** — replay записанной телеметрии (инфраструктура для замеров spike).
