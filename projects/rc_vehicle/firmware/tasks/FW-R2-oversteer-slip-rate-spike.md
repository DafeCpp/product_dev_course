# FW-R2 — OversteerGuard: ложный всплеск slip_rate после простоя

**Источник:** `firmware/CODE_REVIEW.md` → Review 2026-06-10, R2
**Приоритет:** HIGH
**Статус:** [x] Выполнено (2026-06-11)
**Файлы:** `common/stabilization_pipeline.cpp:128-162`

## Проблема

В `OversteerGuard::Process()` ветка «малая скорость / малый yaw rate»
(`:148-153`) сбрасывает `prev_slip_deg_ = 0.0f`. На первом тике после
превышения порогов производная вычисляется как
`slip_rate = (slip − 0) / dt_sec` при `dt_sec ≈ 0.002` — значение в сотни раз
больше реального.

Последствие: условие `|slip_rate| > rate_thresh_deg_s` на первом тике
выполняется всегда, детекция вырождается в проверку одного
`slip_thresh_deg` → ложные срабатывания и сброс газа
(`throttle_reduction`) при обычном входе в поворот.

## Предлагаемое решение

В ветке деактивации сохранять реальное значение вместо нуля:

```cpp
if (std::abs(ekf_->GetYawRate()) < kMinYawRateRad ||
    ekf_->GetSpeedMs() < kMinSpeedMs) {
  oversteer_active_ = false;
  prev_slip_deg_ = slip;   // было: 0.0f
  return;
}
```

Дополнительно (опционально, обсуждаемо): флаг `first_active_tick_` — пропускать
оценку `slip_rate` на первом тике после реактивации, т.к. slip за время простоя
мог измениться скачком.

Внимание: `slip_rate` уже посчитан выше по `prev_slip_deg_` до early-return
(`:137-138`) — при фиксе убедиться, что порядок вычислений не оставляет stale
значение.

рассчитанных по реальной производной; существующие тесты guard'а проходят.
