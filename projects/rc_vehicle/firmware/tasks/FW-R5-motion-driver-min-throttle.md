# FW-R5 — MotionDriver: min_effective_throttle применяется и в PID-режиме

**Источник:** `firmware/CODE_REVIEW.md` → Review 2026-06-10, R5
**Приоритет:** LOW
**Статус:** [ ] Не начато
**Файлы:** `common/motion_driver.cpp:104-108`

## Проблема

Комментарий: «Минимальный рабочий газ (только для LinearRamp)». Код:

```cpp
if (config_.min_effective_throttle > 0.0f && throttle > 0.0f &&
    throttle < config_.min_effective_throttle) {
  throttle = config_.min_effective_throttle;
}
```

Условие не проверяет `accel_mode` — блок выполняется и в `AccelMode::Pid`,
где может подбросить throttle поверх PI-коррекции (PI рассчитывает на
непрерывный выход; ступенька до `min_effective_throttle` мешает сходимости
на малом газе).

## Предлагаемое решение

Выяснить фактическое намерение и привести код/комментарий в соответствие:

- если ограничение нужно только для LinearRamp — добавить
  `config_.accel_mode == AccelMode::LinearRamp` в условие;
- если нужно в обоих режимах (преодоление трения покоя до breakaway) —
  исправить комментарий и убедиться, что PI-фаза не конфликтует
  (в PID-режиме до breakaway работает open-loop рампа — возможно,
  ограничение уместно именно там, а не после).

**Рекомендация ревью:** первый вариант (ограничить LinearRamp'ом, как
заявлено в комментарии): в PID-режиме трение покоя уже преодолевается
open-loop рампой фазы A, а ступенька `min_effective_throttle` поверх
PI-выхода фазы B мешает сходимости на малом газе.
