# FW-S2.6 — Валидация модели на реальных поездках (Python, fitting)

**Источник:** декомпозиция эпика [FW-S2](FW-S2-sil-physics-model-epic.md), 2026-06-17
**Тип:** инфраструктура тестирования (Фаза 4 — валидация модели)
**Язык:** Python (numpy/scipy/matplotlib; прошивка **не нужна**)
**Приоритет:** MEDIUM
**Статус:** [ ] Не начато
**Файлы (при реализации):** `firmware/sim/validation/` (скрипты подгонки/метрик),
`firmware/sim/reports/` (отчёт + графики).

## Зачем

Мост sim↔реальность: closed-loop ([FW-S2.5](FW-S2.5-closed-loop-sil.md)) верен лишь
настолько, насколько физ-модель совпадает с записанными поездками. Здесь проверяем и
подгоняем модель против реальных логов. Прошивка в этой фазе не участвует — это модель
против записанных команд, поэтому **чистый Python** (scipy.optimize, без `sim_host`).

## Объём

- Прогнать модель Фазы 2 ([FW-S2.4](FW-S2.4-python-vehicle-model.md)) записанными
  командами (`rc_throttle/rc_steering` из `telemetry_log_*.csv`) и сравнить
  предсказанные `gyro_z`/`accel`/`yaw`/скорость с записанными.
- **Метрика ошибки** на каждый канал (RMSE/корреляция); порог приёмки «модель
  достаточно хороша».
- **Подгонка `SimParams`** под минимум ошибки (scipy.optimize / простой перебор).
- **Графики** предсказание-vs-запись по каналам (matplotlib).
- **Артефакт:** значения параметров + отчёт «насколько модель совпадает с железом» по
  имеющимся логам (наклон, прямая, занос, задний ход).
- Golden-набор — общий с [FW-S2.2](FW-S2.2-python-replay-harness.md): один набор
  служит и replay-регрессии, и валидации.

## Критерии приёмки

- [ ] Отчёт с метриками (RMSE/корреляция) по каналам на ≥2 логах.
- [ ] Зафиксированные подогнанные `SimParams` (с единицами/провенансом).
- [ ] Явный вывод, где модель применима, а где — нет (обоснование доверия к
  closed-loop [FW-S2.5](FW-S2.5-closed-loop-sil.md)).
