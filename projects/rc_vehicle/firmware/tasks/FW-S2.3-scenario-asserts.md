# FW-S2.3 — Сценарные replay-ассерты на golden-эпизодах

**Источник:** декомпозиция эпика [FW-S2](FW-S2-sil-physics-model-epic.md), 2026-06-17
**Тип:** инфраструктура тестирования (Фаза 1 — replay, сценарии)
**Язык:** Python
**Приоритет:** MEDIUM
**Статус:** [ ] Не начато
**Файлы (при реализации):** `firmware/sim/tests/` (сценарные pytest),
`tests/fixtures/rides/` (профильные golden-вырезки + провенанс).

## Зачем

Инварианты ([FW-S2.2](FW-S2.2-python-replay-harness.md)) ловят грубые поломки. Этот шаг
добавляет **поведенческие** ассерты на представительных эпизодах — превращает реально
найденные баги в регрессии, которые ловятся из данных без железа.

## Объём

Профильные golden-вырезки + сценарные ассерты (допуски, не точные float):
- **Наклон ~20°** → `heading_deg`/PCA-курс стабилен ([FW-R3](FW-R3-mag-frame-mix.md),
  [FW-R14](FW-R14-madgwick-yaw-drift-at-tilt.md); σ ниже порога).
- **Failsafe-эпизод** → нейтраль PWM ([FW-R1](FW-R1-failsafe-trim-override.md)).
- **Занос** → `oversteer_active` срабатывает корректно ([FW-R2](FW-R2-oversteer-slip-rate-spike.md)).
- **Прямая** → курс не дрейфит сверх порога.
- **Задний ход** → руль не осциллирует без ввода (**FW-R22**).

Нарезка эпизодов — по `test_marker`/`drive_mode` (**FW-R18**).
Каждый эпизод — отдельный pytest-кейс со своим провенансом (дата, сценарий, что
проверяем).

## Критерии приёмки

- [ ] ≥3 сценарных кейса на реальных вырезках, зелёные в pytest.
- [ ] Ассерты — на допуски/инварианты, устойчивы к мелким правкам фильтров.
- [ ] У каждой фикстуры записан провенанс.
