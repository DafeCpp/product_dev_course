# FW-R3 — Смесь систем координат при передаче магнитометра в Madgwick

**Источник:** `firmware/CODE_REVIEW.md` → Review 2026-06-10, R3
**Приоритет:** MEDIUM
**Статус:** [x] Код+тесты готовы (2026-06-11) — НЕ МЕРЖИТЬ до валидации на железе/логах
**Файлы:** `common/control_components.cpp:169-185`, `common/madgwick_filter.cpp:121-233`

## Проблема

При валидной mag-калибровке в `MadgwickFilter::UpdateWithMag()` передаётся
вектор `(px, py, dot_n)`:

- `px, py` — x/y-компоненты проекции вектора магнитного поля на
  калибровочную плоскость, выраженные **в СК датчика**;
- `dot_n` — скалярная проекция вдоль нормали калибровочной плоскости.

Это согласованный вектор только в частном случае, когда нормаль плоскости
совпадает с осью Z датчика. При наклонном монтаже IMU (который весь
vehicle-frame-механизм `SetVehicleFrame()` специально поддерживает) компоненты
относятся к разным базисам → искажение yaw в 9DOF-режиме.

При этом Madgwick сам устраняет зависимость от магнитного склонения
(`bx = sqrt(hx²+hy²)` в `madgwick_filter.cpp:175`), т.е. предварительная
проекция не нужна.

## Предлагаемое решение

Передавать полный калиброванный вектор, как уже сделано в ветке без
калибровки (`:181-183`):

```cpp
filter_.UpdateWithMag(raw_ax, raw_ay, raw_az, data_.gx, data_.gy, data_.gz,
                      mag_cal.mx, mag_cal.my, mag_cal.mz, dt_sec);
```

PCA-проекция остаётся только для вычисления `heading_deg_` (там она уместна).

## Валидация

Изменение влияет на оценку ориентации — **обязательна проверка на реальных
данных**:

- [ ] Запись телеметрии (`telemetry_log_*.csv`) с нормальным монтажом: yaw до/после фикса не деградирует
- [ ] Запись с наклонным монтажом (~15-20°): yaw после фикса стабильнее/точнее
- [ ] Сходимость yaw к mag-heading при неподвижности

## Критерии приёмки

Yaw в 9DOF-режиме корректен при наклонном монтаже; нет регрессии при
нормальном монтаже (сравнение на записанных логах).
