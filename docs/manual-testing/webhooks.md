# Сценарии: Webhooks (подписки и доставки)

Раздел **Webhooks** (`/webhooks`): CRUD подписок на события, журнал доставок, повтор доставки,
фильтрация по проекту.

**Где реализовано:**
- Страница `pages/Webhooks.tsx`; API `src/api/webhooks.ts`.
- Подписки: `GET/POST /api/v1/webhooks`, `DELETE /api/v1/webhooks/{id}` (все с `project_id`).
- Доставки: `GET /api/v1/webhooks/deliveries?project_id=&status=`, повтор — `POST /api/v1/webhooks/deliveries/{id}:retry`.
- Поля формы: Target URL, Secret (опц.), Типы событий (через запятую).

**Предусловие:** авторизован как `admin`; **выбран проект** (важно — см. BUG-F-014).

> ⚠️ Регресс-точка [BUG-F-014](https://linear.app/lostpointer/issue/LOS-7/bug-f-014-webhooks-page-sends-requests-without-project-id-400-bad):
> на пустом воркспейсе (нет выбранного проекта) страница слала `GET /api/v1/webhooks(/deliveries)`
> **без `project_id` → `400`**. Проверять и с выбранным проектом, и на пустом воркспейсе.

---

### TC-WHK-01 — Список подписок и фильтр по проекту
**Предусловие:** открыт `/webhooks`, выбран проект.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Открыть `/webhooks` с выбранным проектом | `GET /api/v1/webhooks?project_id=…` → `200`; таблица подписок; консоль чистая |
| 2 | Открыть на пустом воркспейсе (0 проектов) | Запрос **не** уходит без `project_id`; нет `400` в консоли (проверка BUG-F-014) |
| 3 | Переключить проект | Список подписок пере-фильтровывается |

---

### TC-WHK-02 — Создание подписки
**Предусловие:** выбран проект.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | «Создать webhook»: заполнить Target URL, типы событий (через запятую), опц. Secret | Валидация полей проходит |
| 2 | Отправить | `POST /api/v1/webhooks?project_id=…` → `201`; тост «Webhook создан»; подписка в списке |
| 3 | (негатив) Невалидный URL / пустые типы событий | Клиентская/серверная валидация, `400`, тост «Не удалось создать webhook» |

---

### TC-WHK-03 — Удаление подписки
**Предусловие:** есть подписка.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | «Удалить» → подтверждение «Удалить webhook?» | Диалог подтверждения |
| 2 | Подтвердить | `DELETE /api/v1/webhooks/{id}` → `200/204`; тост «Webhook удалён»; исчезла из списка |

---

### TC-WHK-04 — Журнал доставок и повтор
**Предусловие:** есть подписка с доставками (Delivered/Failed/Pending).

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Открыть вкладку доставок | `GET /api/v1/webhooks/deliveries?project_id=…` → `200`; колонки Событие/Статус/Попытки/Время |
| 2 | Фильтр по статусу (Failed) | Список фильтруется по `status` |
| 3 | «Повторить» для Failed-доставки | `POST /api/v1/webhooks/deliveries/{id}:retry` → `200`; тост «Повторная доставка запрошена»; статус → retrying/pending |

---

### TC-WHK-05 — RBAC / изоляция по проекту (негатив)
| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Пользователь без прав в проекте открывает Webhooks проекта | `403`, данные чужого проекта не отдаются |
| 2 | Retry доставки из чужого проекта | `403/404` |

## Не покрыто / на доработку
- Проверка фактической HMAC-подписи (`Secret`) на стороне получателя.
- Политика ретраев/экспоненциальный backoff (свериться со спецификацией webhook-воркера).
