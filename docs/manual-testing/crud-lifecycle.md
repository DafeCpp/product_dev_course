# Сценарии: CRUD и жизненный цикл сущностей

Создание/редактирование/удаление и переходы state machine для `project → experiment → run → capture session`. Дополняет [`e2e-happy-path.md`](e2e-happy-path.md) (тот покрывает happy-path; здесь — правки, удаления и негативные переходы статусов).

**State machine (из `experiment_service/domain/enums.py`):**
- `ExperimentStatus` / `RunStatus` / `CaptureSessionStatus`: `draft → running → succeeded | failed`, и `→ archived`.
- `ConversionProfileStatus`: `draft → scheduled → active → deprecated`.

**Общее предусловие:** авторизован как `admin` (`superadmin` имеет полный доступ ко всем проектам).

---

### TC-CRUD-01 — Создание и редактирование проекта
**Предусловие:** авторизован, открыт `/projects`.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | «Создать проект», имя `Manual QA Project`, описание | Проект появился в списке, открыт/выбран как активный |
| 2 | Открыть проект, изменить описание, сохранить | Изменения сохранены, видны после reload |
| 3 | Проверить, что активный `project_id` прокидывается в запросы Experiments/Sensors | Списки грузятся в контексте проекта (нет `400 project_id is required`) |

**Факт (2026-06-10):** ✅ Проект `QA Idempotency Run` (создан через API) авто-выбран в селекторе; созданные через API эксперименты (`idem-exp-1`, `idem-race`) видны в UI с корректными статусами. Консистентность API↔UI подтверждена.

### TC-CRUD-02 — Эксперимент: lifecycle статусов
**Предусловие:** есть активный проект.

> ⚠️ Уточнено по факту (2026-06-10): на странице эксперимента **нет** отдельной кнопки «запустить/завершить» — доступны только «Редактировать», «Удалить», «Новый запуск», «Compare Runs». Статусные переходы выполняются на уровне **run** (см. TC-CRUD-04), статус эксперимента производный. Шаги 2-3 относятся к run.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Создать эксперимент `Lifecycle Exp` | Статус `draft` |
| 2 | Создать и запустить run внутри эксперимента | Статус run `running` (см. TC-CRUD-04) |
| 3 | Завершить run как `succeeded` | Статус run `succeeded` |
| 4 | Архивировать эксперимент (`POST /api/v1/experiments/{id}/archive`) | Статус `archived`, эксперимент уходит из активного списка/в фильтр archived |

### TC-CRUD-03 — Невалидный переход статуса (негативный)
**Предусловие:** есть эксперимент в статусе `archived` (из TC-CRUD-02).

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Попытаться перевести `archived → running` (через UI или прямой PATCH) | Переход запрещён: ошибка state machine (`409`/`422`), статус не меняется |

### TC-CRUD-04 — Run: создание и переходы
**Предусловие:** есть эксперимент.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | На странице эксперимента создать run `run-1` (`POST /api/v1/experiments/{id}/runs`) | Run `draft`, открывается `/runs/{run_id}` |
| 2 | Запустить run кнопкой «Запустить» (`draft → running`) | Статус `running`, кнопки сменились на «Завершить»/«Пометить как ошибка» |
| 3 | Завершить кнопкой «Завершить» (`running → succeeded`) | Статус `succeeded`, кнопки действий исчезают (терминальное состояние) |

**Факт (2026-06-10):** ✅ Прогнано через Playwright. Создание run → редирект на `/runs/{id}` (`draft`); «Запустить» → `running`; «Завершить» → `succeeded`. В БД `runs.status='succeeded'`. Консистентно.

### TC-CRUD-05 — Capture session: start/stop
**Предусловие:** есть run (в `draft` или `running`).

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | «Старт отсчёта» (`POST /api/v1/runs/{run_id}/capture-sessions`) | Нативный `prompt` для заметки → активная сессия `running` в блоке «Сессии отсчёта» |
| 2 | «Стоп» → подтвердить (`.../capture-sessions/{session_id}/stop`) | Нативный `confirm` → статус `succeeded`, проставлены остановка и длительность |
| 3 | Повторный stop уже остановленной сессии | Идемпотентно/ошибка перехода — не падает 500 |

**Факт (2026-06-10):** ✅ Прогнано через Playwright. «Старт отсчёта» (заметка `manual QA capture`) → сессия `running`; «Стоп»+confirm → `succeeded`, длительность 13с. В БД `capture_sessions.status='succeeded'`, notes/длительность совпадают.
> ⚠️ UX-наблюдение: старт capture session использует нативный `window.prompt` (заметка), стоп — `window.confirm`. Браузерные нативные диалоги ломаются при подавлении диалогов и плохо стилизуются — кандидат на замену на модалку (см. [`test-reports.md`](test-reports.md)).

### TC-CRUD-06 — Удаление
**Предусловие:** есть эксперимент без зависимых данных и с зависимыми.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Удалить эксперимент без runs (`DELETE /api/v1/experiments/{id}`) | Удалён, исчез из списка |
| 2 | Попытаться удалить эксперимент с активным run | Либо каскад с подтверждением, либо запрет с понятной ошибкой (не 500) |
| 3 | Удалить проект → проверить, что зависимые эксперименты/сенсоры обрабатываются по правилам каскада | Поведение соответствует спецификации, без orphan-записей |

## Не покрыто / на доработку

- Конкурентные переходы статуса (race) — кандидат на интеграционный тест, не на ручной прогон.
- Пагинация и фильтры в больших списках.
