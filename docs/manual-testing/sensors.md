# Сценарии: датчики (инвентарь, токен, error-log, монитор)

CRUD и операционные сценарии раздела **Датчики**: список, регистрация, детали, ротация токена,
журнал ошибок, монитор heartbeat/connection status. Конверсия `raw→physical` и backfill описаны
отдельно в [`telemetry-e2e.md`](telemetry-e2e.md) — здесь **не дублируются**, ставятся ссылки.

**Где реализовано:**
- Список/CRUD: `GET/POST /api/v1/sensors`, `GET/PATCH/DELETE /api/v1/sensors/{id}` (`src/api/sensors.ts`).
- Токен: одноразовая выдача при создании (`SensorRegisterResponse`), ре-выдача — `POST /api/v1/sensors/{id}/rotate-token`.
- Error-log: `GET /api/v1/sensors/{id}/error-log` (отдаётся из telemetry-ingest, см. BUG-B-005 про миграцию).
- Монитор: `GET /api/v1/sensors/status-summary`, `GET /api/v1/sensors/{id}/heartbeat-history?minutes=` (`SensorMonitor.tsx`).
- Мульти-проектность: `GET/POST /api/v1/sensors/{id}/projects`, `DELETE .../projects/{projectId}` (`SensorProjectsSection.tsx`).
- Роуты Portal: `/sensors`, `/sensors/new`, `/sensors/:id`, `/sensor-monitor`.

**Предусловие:** авторизован как `admin`; выбран активный проект (см. [`crud-lifecycle.md`](crud-lifecycle.md)).

---

### TC-SENSOR-01 — Список датчиков и фильтры
**Предусловие:** открыт `/sensors`, в проекте есть ≥1 датчик.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Открыть `/sensors` | Таблица датчиков: колонки Регистрация/Единицы/Heartbeat/Токен/Статус («Активен»/«Неактивен»/«Архивирован»); `GET /api/v1/sensors` → `200`; консоль чистая |
| 2 | Переключить фильтр «Все проекты» ↔ конкретный проект | Список пере-фильтровывается по `project_id` |
| 3 | Пустой проект (0 датчиков) | Пустое состояние без ошибок в консоли |

---

### TC-SENSOR-02 — Регистрация датчика и одноразовый токен
**Предусловие:** открыт `/sensors`, нажата «Регистрация» → `/sensors/new`.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Заполнить форму (name, type, input_unit, display_unit), отправить | `POST /api/v1/sensors` → `201`; редирект/показ деталей |
| 2 | Скопировать показанный **sensor token** | Токен виден достаточно долго (регресс BUG-F-007), копирование работает (фолбэк BUG-F-002/003) |
| 3 | Обновить страницу деталей | Токен **больше не показывается** (одноразовая выдача) |

Подробная привязка к конверсии/ingest — [`telemetry-e2e.md`](telemetry-e2e.md) TC-TELE-01.

---

### TC-SENSOR-03 — Детали датчика
**Предусловие:** есть датчик, открыт `/sensors/:id`.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Открыть детали | Секции: профили конверсии, backfill, проекты, error-log, заметки по калибровке; `GET /api/v1/sensors/{id}` → `200` |
| 2 | До первой телеметрии | `last_heartbeat` пустой |
| 3 | Отредактировать (PATCH) поле (напр. заметки/единицы) | `PATCH /api/v1/sensors/{id}` → `200`, изменения сохранены |

---

### TC-SENSOR-04 — Ротация токена
**Предусловие:** есть датчик, открыты детали.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Выполнить «ротацию токена» | `POST /api/v1/sensors/{id}/rotate-token` → `200`, показан новый токен |
| 2 | Ingest старым токеном | Отклонён (`401`) — старый токен инвалидирован |
| 3 | Ingest новым токеном | Принят (`202`) |

---

### TC-SENSOR-05 — Мульти-проектная привязка
**Предусловие:** есть датчик и ≥2 проекта.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Добавить датчик во 2-й проект (`POST /api/v1/sensors/{id}/projects`) | `200/201`, проект появился в списке |
| 2 | Убрать привязку (`DELETE .../projects/{projectId}`) | `200/204`, проект удалён из списка |
| 3 | (негатив) Убрать привязку из проекта, где нет прав | `403` |

---

### TC-SENSOR-06 — Error-log датчика
**Предусловие:** есть датчик.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Открыть секцию error-log на деталях | `GET /api/v1/sensors/{id}/error-log` → `200 {"entries":[…],"total":N}` (см. регресс BUG-B-005 — миграция telemetry-ingest 005) |
| 2 | Пагинация (limit/offset) | Корректная выборка, без `500` |

---

### TC-SENSOR-07 — Монитор: heartbeat и connection status
**Предусловие:** датчик отправлял телеметрию (см. [`telemetry-e2e.md`](telemetry-e2e.md) TC-TELE-03).

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Открыть `/sensor-monitor` | Датчики со статусом подключения и историей heartbeat; `status-summary` и `heartbeat-history` → `200` |
| 2 | Прекратить отправку, подождать таймаут | Connection status → offline/stale |
| 3 | Фильтр «Все проекты» ↔ проект | Список фильтруется |
