# Сценарии: RBAC и роли доступа

Многопользовательские сценарии: проектные роли `owner` / `editor` / `viewer`, инвайты, выдача/отзыв ролей, проверка запретов и изоляции между проектами (IDOR).

**Модель (из `auth_service/domain/models.py`):** проектные роли — `owner` / `editor` / `viewer`. Системная роль `superadmin` имеет доступ ко всему. Управление ролями проекта — `/api/v1/projects/{projectId}/roles`, `.../members/{userId}/roles`. Инвайты и пользователи — в auth-service (`/auth/admin/*`).

**Предусловие:** нужны минимум 2-3 пользователя помимо `admin`. Создать через регистрацию (`/register`) или инвайты (`POST /auth/admin/invites`).

> ⚠️ **Важно (выявлено 2026-06-10):** выдача/отзыв проектных ролей через auth-proxy **не работает** — `/api/v1/projects/*/roles` отдаёт 404 (см. [BUG-F-015](../bugs.md)). Для прогона enforcement-сценариев роли выдавались в обход прокси, прямо в auth-service (`:8001`, `Authorization: Bearer <admin_token>`), payload `{"role_id":"<uuid>"}` (role_id: owner `…010`, editor `…011`, viewer `…012`).

### TC-RBAC-01 — Создание пользователей через инвайты
**Предусловие:** авторизован как `admin`, открыт `/admin/users`.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Создать инвайт (`POST /auth/admin/invites`) | В таблице появился инвайт-токен, кнопка «Копировать» работает (в HTTP-контексте — фолбэк, см. BUG-F-002) |
| 2 | Зарегистрировать пользователя `editor_user` по инвайт-токену | Аккаунт создан; инвайт помечается **использованным** (`used_at` не пустой — см. BUG-F-011) |
| 3 | Повторно использовать тот же инвайт-токен | Отклонено: инвайт single-use (см. [`idempotency-auth-hardening.md`](idempotency-auth-hardening.md) TC-AUTHH-02) |

### TC-RBAC-02 — Выдача роли editor и проверка прав
**Предусловие:** есть проект (owner = `admin`) и пользователь `editor_user`.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Выдать `editor_user` роль `editor` в проекте (`POST /api/v1/projects/{id}/members/{userId}/roles`, `role: editor`) | Пользователь в списке участников с ролью editor |
| 2 | Войти как `editor_user`, открыть проект | Проект виден; можно создавать/править эксперименты, сенсоры |
| 3 | Попытаться управлять ролями участников проекта | **Запрещено** (управление ролями — право owner): `403` |

**Факт (2026-06-10):** ✅ editor создал эксперимент через прокси (`201`). Попытка выдать себе роль owner → `403: Missing permission: project.members.change_role`.

### TC-RBAC-03 — Роль viewer: только чтение
**Предусловие:** есть пользователь `viewer_user` с ролью `viewer` в проекте.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Войти как `viewer_user`, открыть проект/эксперименты | Данные видны (read) |
| 2 | Попытаться создать/изменить/удалить эксперимент или сенсор | **Запрещено**: `403`, кнопки мутаций скрыты/disabled |
| 3 | Попытаться выдать себе роль выше | Запрещено: `403` |

**Факт (2026-06-10):** ✅ viewer читает список экспериментов (`200`); создание эксперимента → `403: Missing permission: experiments.create`.

---

### TC-RBAC-04 — Отзыв роли и защита единственного owner
**Предусловие:** проект с owner `admin` и участником `editor_user`.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Отозвать роль у `editor_user` | Доступ к проекту пропал; при заходе `403`/проект не виден |
| 2 | Попытаться снять роль owner у единственного владельца | **Запрещено**: «Cannot remove the sole owner» (см. `permission.py`), `409`/`400` |

**Факт (2026-06-10):** ✅ Снятие owner-роли с единственного владельца (admin) → `409: Cannot revoke the last owner of a project`.

---

### TC-RBAC-05 — Изоляция между проектами (IDOR, негативный)
**Предусловие:** проект A (доступен `editor_user`) и проект B (НЕ доступен `editor_user`).

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Войти как `editor_user` | — |
| 2 | Запросить сущность проекта B напрямую по ID (подменить `project_id`/ресурсный ID в запросе) | **Запрещено**: `403`/`404`, данные чужого проекта не отдаются |
| 3 | Скачать artifact/backfill из чужого проекта | Запрещено (project-scoped, см. недавний фикс IDOR в `66085f5`) |

**Факт (2026-06-10):** ✅ editor (член только проекта A) к проекту B: эксперименты → `403: Missing permission: experiments.view`; сам проект (`GET /projects/{B}`) → `403: Missing permission: project.members.view`.

### TC-RBAC-06 — Системные роли (admin-зона)
**Предусловие:** авторизован как `admin` (`superadmin`).

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Открыть `/admin/system-roles`, создать системную роль | Создаётся без ошибки CSRF (см. BUG-F-010) |
| 2 | Войти обычным пользователем, открыть `/admin/users` | Доступ к админ-зоне запрещён |
