# Сценарии: Аудит-лог

Раздел **Аудит** (`/admin/audit`): журнал системных событий и действий пользователей, фильтры,
запись событий из сервисов.

**Где реализовано:**
- Страница `pages/AuditLog.tsx`; API `src/api/audit.ts` → `GET /api/v1/audit-log`.
- Фильтры: `actor_id`, `action`, `scope_type` (`system|project`), `scope_id`, `target_type`,
  `target_id`, `from`, `to`, `limit`, `offset`.
- Колонки UI: Время / Пользователь / Действие / Область (Система/Проект) / Цель / Детали.
- Доступ к разделу: nav требует `audit.read`.

> ⚠️ Регресс-точка: в логах experiment-service ранее наблюдалось `Audit write failed status=404
> action='experiment.create'` — запись аудита получала `404` (см. отчёт 2026-06-10, TC-IDEM).
> Проверить, что события фактически **пишутся** и видны в разделе.

**Предусловие:** авторизован как `admin` (`audit.read`).

### TC-AUDIT-01 — Открытие журнала
**Предусловие:** открыт `/admin/audit`.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Открыть раздел | `GET /api/v1/audit-log` → `200`; таблица событий; консоль чистая |
| 2 | Проверить колонки | Время/Пользователь/Действие/Область/Цель/Детали заполнены |

**Факт (2026-07-16):** ⚠️ `GET /api/v1/audit-log` → `200`, консоль чистая, но таблица **пустая** («Записей аудит-лога не найдено») несмотря на выполненные до этого create-действия (project/experiment/run) — см. TC-AUDIT-02.

---

### TC-AUDIT-02 — Запись событий (сквозная проверка)
**Предусловие:** открыт аудит.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | В другой вкладке выполнить действие (создать эксперимент/сенсор/роль) | Действие успешно |
| 2 | Обновить аудит-лог | Появилась запись с соответствующим `action` и `target` (проверка «Audit write 404» — событие реально записано) |

**Факт (2026-07-16):** ❌ Регресс подтверждён и root-caused. Создание проекта/эксперимента/run через Portal прошло успешно (`201`), но в аудит-логе — 0 записей. Логи experiment-service: `event='Audit write failed' status=404 action='experiment.create'` и `action='run.create'`. Причина: `.env` задаёт `AUTH_SERVICE_URL=http://auth-service:8001` **без** суффикса `/api/v1`, перебивая compose-дефолт (который суффикс включает) — `audit_client.py` предполагает суффикс уже в base URL и шлёт `POST http://auth-service:8001/internal/audit` вместо `.../api/v1/internal/audit` → `404`. Заведён [LOS-190](https://linear.app/lostpointer/issue/LOS-190) (High).
