# Сценарии: Аудит-лог

Раздел **Аудит** (`/admin/audit`): журнал системных событий и действий пользователей, фильтры,
запись событий из сервисов.

**Где реализовано:**
- Страница `pages/AuditLog.tsx`; API `src/api/audit.ts` → `GET /api/v1/audit-log`.
- Фильтры: `actor_id`, `action`, `scope_type` (`system|project`), `scope_id`, `target_type`,
  `target_id`, `from`, `to`, `limit`, `offset`.
- Колонки UI: Время / Пользователь / Действие / Область (Система/Проект) / Цель / Детали.
- Доступ к разделу: nav требует `audit.read`.

> ✅ Регресс-точка закрыта (2026-07-18): в логах experiment-service ранее наблюдалось `Audit write
> failed status=404 action='experiment.create'` (см. отчёт 2026-06-10, TC-IDEM) — исправлено в
> [LOS-190](https://linear.app/lostpointer/issue/LOS-190). Отдельно от этого UI не показывал уже
> записанные события из-за расхождения контракта backend/frontend — исправлено в
> [LOS-195](https://linear.app/lostpointer/issue/LOS-195). Оба фикса подтверждены живым прогоном.

**Предусловие:** авторизован как `admin` (`audit.read`).

### TC-AUDIT-01 — Открытие журнала
**Предусловие:** открыт `/admin/audit`.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Открыть раздел | `GET /api/v1/audit-log` → `200`; таблица событий; консоль чистая |
| 2 | Проверить колонки | Время/Пользователь/Действие/Область/Цель/Детали заполнены |

**Факт (2026-07-16):** ⚠️ `GET /api/v1/audit-log` → `200`, консоль чистая, но таблица **пустая** («Записей аудит-лога не найдено») несмотря на выполненные до этого create-действия (project/experiment/run) — см. TC-AUDIT-02.

**Факт (2026-07-18, повторный прогон после фикса [LOS-195](https://linear.app/lostpointer/issue/LOS-195)):** ✅ Таблица рендерит записи (33 шт. в тестовой БД: `auth.login`, `experiment.create`, `role.grant`, `auth.password_change`, `auth.register`, `project.create`, `auth.bootstrap`). Колонки Время/Действие/Область/Цель заполнены; колонка «Пользователь» показывает `actor_id` (UUID) — резолвинга в username пока нет ни на backend, ни на frontend (не регрессия, а не реализованная фича). Консоль чистая. Причина исходной пустоты: `GET /api/v1/audit-log` отдавал голый JSON-массив, а фронтенд ждал `{entries,total,limit,offset}` — `data.entries` был всегда `undefined`. Важно при повторной проверке: нужен полный ребилд образа `auth-service` (`docker compose build`, без кэша от старого образа) — простой рестарт контейнера подхватывает старый код и даёт ложноотрицательный результат.

### TC-AUDIT-02 — Запись событий (сквозная проверка)
**Предусловие:** открыт аудит.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | В другой вкладке выполнить действие (создать эксперимент/сенсор/роль) | Действие успешно |
| 2 | Обновить аудит-лог | Появилась запись с соответствующим `action` и `target` (проверка «Audit write 404» — событие реально записано) |

**Факт (2026-07-16):** ❌ Регресс подтверждён и root-caused. Создание проекта/эксперимента/run через Portal прошло успешно (`201`), но в аудит-логе — 0 записей. Логи experiment-service: `event='Audit write failed' status=404 action='experiment.create'` и `action='run.create'`. Причина: `.env` задаёт `AUTH_SERVICE_URL=http://auth-service:8001` **без** суффикса `/api/v1`, перебивая compose-дефолт (который суффикс включает) — `audit_client.py` предполагает суффикс уже в base URL и шлёт `POST http://auth-service:8001/internal/audit` вместо `.../api/v1/internal/audit` → `404`. Заведён [LOS-190](https://linear.app/lostpointer/issue/LOS-190) (High).

**Факт (2026-07-18, повторный прогон):** ✅ Фикс [LOS-190](https://linear.app/lostpointer/issue/LOS-190) подтверждён напрямую в БД (`select * from audit_log order by timestamp desc limit 1` — свежая запись `experiment.create` присутствует) и через API. После фикса [LOS-195](https://linear.app/lostpointer/issue/LOS-195) запись также видна в UI без обновления вручную — сквозной цикл «действие → запись в БД → отображение в разделе Аудит» работает целиком.

### TC-AUDIT-03 — Фильтры
**Предусловие:** в журнале есть записи.

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | Фильтр по `action` | Выборка сужается по действию |
| 2 | Фильтр по `scope_type=project` + `scope_id` | Только события проекта |
| 3 | Диапазон `from`/`to` | Только события за период; пустой период → пустая выборка без ошибок |

**Факт (2026-07-18):** ✅ Проверен п.1 (`action=auth.login`): `GET /api/v1/audit-log?action=auth.login&...` уходит корректно, выборка сужается до записей с этим действием. Пп. 2–3 (scope_type/scope_id, from/to) не перепроверялись в этом прогоне.
